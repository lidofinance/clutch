# Roadmap

A phase starts after the previous phase's gates close. Dates apply only when an external process sets them.

| Phase | Work | Gate |
|---|---|---|
| 0. Decisions | Accept design ADRs 005–011 and process ADR 012; EM has accepted setup ADRs 001–004. Close or defer open decisions. Written confirmation of no standing approvals and consent to be named are due before the launch cap lifts, not before launch (OD-54). | EM accepts each ADR. Each open decision is closed or explicitly deferred. |
| 1. Specification | Write architecture, roles matrix, permission model, threat model and monitoring specifications. Give each invariant an ID. Keep the constellation policy, its compiler, its artifact and the fork tests in line with the accepted ADRs; the port exists since 2026-10-06 (OD-33). Set up the Lido Zodiac workspace (OD-35). Write the control matrix and screening rule list (OD-39, OD-45). Send the screening vendor its questions and the policy provider the UI requirements (OD-44, OD-84 to OD-88). Fork-test the CoW order signer and ComposableCoW from Safe v1.5.0 behind a Roles modifier (OD-43). Draft runbooks. Import the budget computation after mandate approval. | The acceptor accepts the specifications. Each invariant has an ID and names its ADR. |
| 2. Build | Build the round-trip check. Add the orders account, first-loss Safe, their modifiers and permissions, the `first-loss` and `first-loss-burn` roles, and the burn factory (OD-42, OD-43, OD-60, OD-67). Build Easy Track factories, each with its emergency exit through exit-governance (OD-49), and a budget factory that can set several keys in one motion (OD-94). Build the command that computes each Safe batch's hash again (OD-92). Configure funding. Build reporting, buffer detection, the mandate's rule data, and the comparison of Lido's reading with the policy provider's (OD-40, OD-84, OD-87). Enforce invariant-to-test coverage and one-command verification. Run fork tests in CI on `main` and in the merge queue. Keep the archive RPC key in repository secrets; never use it on pull requests (OD-52). | CI enforces a passing test for each invariant. One command verifies each permission change. |
| 3. Assurance | Audit factories, policy and deployment externally. Lido reviews the guard's post-audit change before the launch cap lifts. Lido reviews CoW's order signer; this repository found no audit. Lido reviews the TWAP handler unless an audit covers it (OD-43). Drill each emergency and technical action on a fork. Check the LIP against the specifications. | Audit findings are closed or accepted. Each emergency drill starts its action within six hours. |
| 4. Governance and deployment | Publish the mandate on the forum and hold its Snapshot. Appoint the emergency Safe's fifth signer by Snapshot: a member of neither the committee nor the Emergency Brakes multisig (OD-58). Prepare the LIP and enabling on-chain vote, with the Safe batches published for review (OD-92). Rehearse the vote and the batches at a recent block, with the check of the shared payment permission, before the vote starts and again before it executes (OD-92, OD-93). Repeat Safe release, advisory and bug-bounty checks shortly before the vote (OD-17). Deploy without the guard, under the one-million-dollar cap that the committee keeps by procedure (OD-54, OD-55). The Growth Committee transfers first-loss Earn shares to the first-loss Safe. Then enact the seed motion within the cap. | The repository is public by deployment. Safe checks find no change on the vault's paths, or EM decides again. A fork rehearsal of the vote verifies the orders account's CoW fallback handler, ComposableCoW domain verifier and relayer approvals. The vote passes. Deployed state matches the artifacts. |
| 5. Operation | Publish monthly reports and fortnightly cap readings on IPFS. Change budgets by motion only after an event (OD-56). Repeat drills. Before the cap lifts, set the guard on the committee's Safe with bypass mode off (OD-83). Put the screening vendor's terms in place and complete Lido's review of the post-audit guard change. The committee's forum post then lifts the cap (OD-54). | Continuous operation. |

## Standing gates

- **Hard gates:** the three gates of the [product brief](docs/product/brief.md#hard-gates), traceability, one-command verification and six hours, hold in every phase.
- Financial figures enter documents only if an attested computation produced them.
- Only EM or the Treasury Management Committee accepts ADRs.
