# Roadmap

A phase starts after the previous phase's gates close. Dates apply only when an external process sets them.

| Phase | Work | Gate |
|---|---|---|
| 0. Decisions | Accept design ADRs 005–011, 013 and 014, and process ADR 012; EM has accepted setup ADRs 001–004. Close or defer open decisions. The vendor's written confirmation of no standing approvals is due before the second tranche's vote, and its consent to be named before the mandate is posted (OD-54, OD-121). | EM accepts each ADR. Each open decision is closed or explicitly deferred. |
| 1. Specification | Write architecture, roles matrix, permission model, threat model and monitoring specifications. Give each invariant an ID. Keep the constellation policy, its compiler, its artifact and the fork tests in line with the accepted ADRs (OD-33). Set up the Lido Zodiac workspace (OD-35). Write the control matrix and screening rule list (OD-39, OD-45). Send the screening vendor its questions and the policy provider the UI requirements (OD-44, OD-84 to OD-88). Draft runbooks. Import the budget computation after mandate approval. | The acceptor accepts the specifications. Each invariant has an ID and names its ADR. |
| 2. Build | Build the round-trip check. Add a Lido Lend fund's role to the first-loss modifier (OD-107, OD-131). Finish the universal Easy Track factory: the shapes of the launch protocols with their emergency exits through exit-governance (OD-49), the Lido Lend fund's shape (OD-100 to OD-107, OD-131, OD-132), and the removal of a token from the orders account's lists. Report the factory's size and gas to EM before any fallback to raw writes (OD-102); the prototype's measures are in [its research note](docs/research/universal-factory-prototype-2026-11-05.md). Build the `motion` command that turns a merged policy change into a motion. Build the command that computes each Safe batch's hash again (OD-92). Build reporting, with the TMC-6 line for the whole treasury, the mandate's rule data, and the comparison of Lido's reading with the policy provider's (OD-84, OD-87, OD-111). Enforce invariant-to-test coverage and one-command verification. Run fork tests in CI on `main` and in the merge queue. Keep the archive RPC key in repository secrets; never use it on pull requests (OD-52). | CI enforces a passing test for each invariant. One command verifies each permission change. |
| 3. Assurance | Audit the universal Easy Track factory, CoW's order signer, the policy and the deployment externally. The order signer has no known audit, so it counts as new code (OD-96). Lido reviews the guard's post-audit change before the second tranche's vote. Lido reviews the TWAP handler unless an audit covers it (OD-43). Drill each emergency and technical action on a fork. Check the LIP against the specifications. | Audit findings are closed or accepted. Each emergency drill starts its action within six hours. |
| 4. Governance and deployment | Publish the mandate on the forum and hold its Snapshot. Appoint the emergency Safe's fifth signer by Snapshot: a member of neither the committee nor the Emergency Brakes multisig (OD-58). Prepare the LIP and enabling on-chain vote, with the Safe batches published for review (OD-92). Rehearse the full vote, with the first tranche inside it, and the batches at a recent block (OD-92, OD-106; [enabling-vote spec](docs/specs/enabling-vote.md#the-full-rehearsal)). Repeat Safe release, advisory and bug-bounty checks shortly before the vote (OD-17). Deploy without the guard. The enabling vote pays the first tranche, one million dollars, which is the launch cap (OD-54, OD-55, OD-106). The Growth Committee transfers first-loss Earn shares to the first-loss Safe. | Safe checks find no change on the vault's paths, or EM decides again. A fork rehearsal of the vote verifies the orders account's CoW fallback handler, ComposableCoW domain verifier and relayer approvals. The vote passes. Deployed state matches the artifacts. |
| 5. Operation | Publish monthly reports and fortnightly cap readings on IPFS. Change budgets by motion only after an event (OD-56). Repeat drills. Before the second tranche's vote starts, set the guard on the committee's Safe with bypass mode off; the Zodiac UI requests the vendor's approval from that moment (OD-83, OD-121). Put the screening vendor's terms in place and complete Lido's review of the post-audit guard change. The second tranche's vote is the only way above the cap (OD-106, OD-121). Fund later tranches by vote only when needed. | Continuous operation. |

## Standing gates

- **Hard gates:** the three gates of the [product brief](docs/product/brief.md#hard-gates), traceability, one-command verification and six hours, hold in every phase.
- Financial figures enter documents only if an attested computation produced them.
- Only EM or the Treasury Management Committee accepts ADRs.
